# Structured Writing

雑多な箇条書き（Brain Dump）を、SCQA と階層構造を使って整理する。  
整理はユーザーとの **対話型** で進める。初稿を作成後、不足・曖昧な点をユーザーに問いかけ、情報を補完・具体化しながらブラッシュアップする。

## Structured Writing とは

**導入を先頭**に置いた後、**メインメッセージを頂点としたツリー構造** で情報を整理する。

- 導入は SCQA（Situation, Complication, Question, Answer）で構成する。 Answerがメインメッセージ。
- SCQA は十分詳細に書く。
- その後、Answerを支える主張をツリー構造の箇条書きで構成する。
- メインメッセージは常にトップに置く。
- ツリーの親ノードは子ノードの要約
- どの階層でも、その階層から下を捨てても意味が通るようにする
- 1つの親に対する子ノードは2–5個を基本とし、多すぎる場合は再階層化する
- ツリーの各分岐の深さや幅はなるべく均一にする。
- 複数ピラミッド構成に分ける場合、各キーノードにも局所 SCQA を置く。

思い出しフック: **SCQA** / **Top Message** / **2–5 grouping** / **Summary Tree**

## 進め方（対話型フロー）

以下のサイクルを繰り返し、ユーザーが「この構造でよい」と承認するまで反復する。

1. **初稿作成**: 入力情報をもとに構造を組み、Issues も合わせて出力する。
2. **ブラッシュアップ質問**: Issues や曖昧点をまとめてユーザーへ問いかける（1回の対話で複数質問をまとめる）。
3. **反映・再整理**: ユーザーの回答を取り込み Pyramid を更新する。
4. **承認確認**: 「この構造でよいか」をユーザーに確認し、問題なければ次工程へ。問題があれば 2 に戻る。

### ブラッシュアップ質問の観点

**情報の不足**

- 親ノードを支えるのに必要な詳細が不足している分岐について、追加情報をユーザーに問う。  
  例）「Aという主張の下位構造を成立させる情報が不足しています。追加情報はありますか？」
- 子ノードが 6 個以上並ぶ分岐について、中間ノードにまとめるための整理軸があるかを問う。  
  例）「この 7 項目は、そのまま列挙せずに 2-5 個のまとまりへ再階層化したいです。整理軸はありますか？」

**曖昧な表現の具体化**

- NGワード（適切・最適・効率的・効果的・重要・正しく・対応・綺麗・整理 など）が含まれる場合、具体的な意味を確認する。  
  例）「"効率的に" とは具体的にどういう状態を指しますか？」
- 「ユーザー」「担当者」など指示対象が曖昧な語も具体化する。  
  例）「"ユーザー"はブログ読者ですか、それとも顧客ですか？」

**専門用語・略語の確認**

- 想定読者に自明でない可能性がある略語・専門用語は、正式名称・言い換えを確認する。  
  例）「"KPI"は読者に自明ですか？"重要業績評価指標"と表記すべきですか？」

**冗長・重複の整理**

- 同様の内容が複数箇所にある場合、統合可否をユーザーに確認する。

## 出力形式

整理結果はIntroductionおよびContentの2節に配置。 加えて、整理がうまくできない箇所を洗い出してIssuesに記載する。

Introductionは SCQA を一つずつ並べた4アイテムの箇条書きで構成。 各箇条書きの中に、そのアイテムを補足する追加情報を入れることができる。

Contentに、Answerをトップとしたツリー構造の箇条書きを配置。

Issuesに、ツリー構造への整理がうまくできない箇所を列挙。 以下のような課題がありうる。

- XXXに関する詳細がなく、親ノードを十分に支えられない。
- 主張を支えるのに不必要な情報がある。
- 特定の分岐に対して材料が少なく、ツリーの深さや幅が他と大きく異なる。
- 特定の分岐に子ノードが多すぎて、再階層化なしでは読みづらい。
- 途中の階層だけ読むと意味が通らず、下位ノードに依存しすぎている。

```
## Introduction

- {Situation}
    - {Additional Information}
- {Complication}
    - {Additional Information}
- {Question}
    - {Additional Information}
- {Answer}
    - {Additional Information}

## Content

- {Answer}
    - {Child Node A}
        - {Detail A1}
        - {Detail A2}
    - {Child Node B}
        - {Detail B1}
        - {Detail B2}

## Issues

- {Issue 1}
- {Issue 2}
```

## 制約

禁止: 確認なしに情報を追加・補完・推測・意味を拡張する

許可: 並び替え・グルーピング・階層化・上位ノード作成のための最小限の要約・ユーザー回答を反映した情報の具体化と追記
