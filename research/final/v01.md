## shadcn/ui の概要

**shadcn/ui**（<https://ui.shadcn.com/）は、[Radix> UI](<https://www.radix-ui.com/>) と [Tailwind CSS](https://tailwindcss.com/) をベースにした、いわゆる「コンポーネントライブラリ」の新しいアプローチです。

従来のUIライブラリとの最大の違いは、**npm パッケージとしてインストールするのではなく、コンポーネントのソースコードをプロジェクト内に直接コピーして使う**という哲学にあります。作者自身も「これはコンポーネントライブラリではない。コンポーネントライブラリを構築するための方法だ」と述べています。

### 設計原則

| 原則 | 説明 |
|------|------|
| **Open Code** | コンポーネントの実装コードがそのままプロジェクト内に存在し、自由に変更可能 |
| **Composition** | すべてのコンポーネントが共通の composable なインターフェースを持つ |
| **Distribution** | CLIツールによるコンポーネントの配布・インストールの仕組み |
| **Beautiful Defaults** | デフォルトでクリーンかつ一貫性のあるデザイン |
| **AI-Ready** | LLMがコードを読み・理解し・改善しやすい構造 |

### 技術スタック

- **Radix UI**: アクセシビリティ対応の headless UIプリミティブ
- **Tailwind CSS**: ユーティリティファーストCSSフレームワーク
- **TypeScript**: 型安全なコンポーネント
- **対応フレームワーク**: Next.js, Vite, React Router, Astro, TanStack Start/Router, Laravel など

## 使い方の紹介

### 1. インストール（新規プロジェクト）

最も簡単な方法は CLI を使った新規プロジェクト作成です。

```bash
pnpm dlx shadcn@latest create
```

対話式のプロンプトでフレームワーク・アイコンライブラリ・テーマを選択できます。

### 2. 既存プロジェクトへの追加（Next.js の例）

```bash
# Next.js プロジェクトに初期設定を追加
pnpm dlx shadcn@latest init
```

初期化が完了すると `components.json` という設定ファイルが生成されます。

### 3. コンポーネントの追加

必要なコンポーネントを個別に追加します。コンポーネントはプロジェクトの `components/ui/` ディレクトリにソースコードとして追加されます。

```bash
# Button コンポーネントを追加
pnpm dlx shadcn@latest add button

# 複数コンポーネントを一度に追加
pnpm dlx shadcn@latest add button card dialog
```

### 4. 基本的な使用例

```tsx
// components/ui/button.tsx がプロジェクト内に生成される
import { Button } from "@/components/ui/button"

export function MyComponent() {
  return (
    <div>
      {/* variant で見た目を変更 */}
      <Button variant="default">デフォルト</Button>
      <Button variant="outline">アウトライン</Button>
      <Button variant="ghost">ゴースト</Button>
      <Button variant="destructive">削除</Button>

      {/* size で大きさを変更 */}
      <Button size="sm">小</Button>
      <Button size="lg">大</Button>
    </div>
  )
}
```

### 5. コンポーネントのカスタマイズ

`components/ui/button.tsx` を直接編集できます。

```tsx
// components/ui/button.tsx を開いて直接カスタマイズ
const buttonVariants = cva(
  "inline-flex items-center justify-center ...",
  {
    variants: {
      variant: {
        default: "bg-primary text-primary-foreground hover:bg-primary/90",
        // 独自バリアントを追加
        brand: "bg-blue-600 text-white hover:bg-blue-700 font-bold",
        // ...
      },
    },
  }
)
```

### 6. テーマ設定

CSS 変数によるテーマカスタマイズが可能です。

```css
/* globals.css */
:root {
  --background: 0 0% 100%;
  --foreground: 222.2 84% 4.9%;
  --primary: 222.2 47.4% 11.2%;
  /* ... */
}
```

### 各ライブラリの特徴まとめ

#### Material UI (MUI)

Google の Material Design に準拠した最も普及したUIライブラリの一つ。コンポーネント数が豊富で、エンタープライズ向け（MUI X）の DataGrid や Date Picker も充実している。ただしデザインに Material Design のクセが強く、独自デザインへの変更はカスタマイズコストが高い。

#### Ant Design

Alibaba が開発した、特にB2Bや管理画面向けに強いライブラリ。Form や Table などの業務系コンポーネントが非常に充実している。デザインが独特で、コンシューマー向けのすっきりしたUIには不向きなことも。

#### Chakra UI

シンプルで使いやすいAPIと優れたアクセシビリティが特徴。プロップスでのスタイル指定（`<Box p={4} color="red.500">`）が直感的。コンポーネント数はやや少ない。

#### Mantine

フル機能を持つ React コンポーネントライブラリ。Form管理・通知・モーダル管理など多彩なhooksが特徴。Tailwindとの相性はそれほどよくない。

## shadcn/ui の利点

### 1. 完全なカスタマイズ性

コンポーネントのコードがプロジェクト内に直接存在するため、**どんな変更も自由に行える**。ライブラリのAPIやオーバーライドの制約を受けずに、ビジネス要件に合わせた変更が可能。

### 2. バンドルサイズの最適化

npmパッケージとして全コンポーネントをインストールするのではなく、**使用するコンポーネントだけを追加**する。Tree-shanicingにも依存せず、本当に必要なコードしかプロジェクトには入らない。

### 3. 優れたアクセシビリティ

Radix UI の headless コンポーネントをベースにしているため、**キーボードナビゲーション・スクリーンリーダー対応・ARIA属性**がデフォルトで正しく実装されている。

### 4. デザインの中立性

Material Design や Ant Design のような強いデザイン言語を持たないため、**独自のブランドデザインへの適応が容易**。

### 5. Tailwind CSS とのシームレスな統合

すでに Tailwind CSS を使っているプロジェクトなら、スタイリングの哲学が一致するため**既存の開発フローに自然に溶け込む**。

### 6. AI との親和性

コンポーネントコードが手元にあるため、**GitHub Copilot などのAIツールがコンテキストを理解しやすく**、コード補完・生成の精度が高い。

### 7. ベンダーロックインがない

特定のnpmパッケージに依存しないため、**ライブラリの方針変更やメンテナンス停止のリスクが低い**。コードは自分のものなので、原則的にいつでも移行できる。

## shadcn/ui の欠点

### 1. Tailwind CSS が必須

shadcn/ui は Tailwind CSS を前提とした設計のため、**Tailwind を使っていないプロジェクトへの導入は現実的ではない**。CSS-in-JS や CSS Modules を使っているプロジェクトには不向き。

### 2. コンポーネント数が限られる

MUI や Mantine に比べると**コンポーネントの種類が少なく**、複雑なデータグリッドや高機能なDate Pickerなどは別途ライブラリを用意する必要がある。

### 3. アップデートが面倒

従来のライブラリなら `npm update` でアップデートできるが、shadcn/ui は**プロジェクト内のコードをCLIで再取得する方式**。独自カスタマイズとのマージ作業が発生しうる。

### 4. プロジェクト初期セットアップのコスト

インストールして `import` するだけの従来型ライブラリと異なり、**初回セットアップの手順がやや多い**（Tailwind の設定、`components.json` の設定など）。

### 5. 小規模・PoC向きではない

コンポーネントをひとつひとつ追加していく方式は、素早くプロトタイプを作りたい場合や小規模プロジェクトには**オーバーエンジニアリングになりうる**。

### 6. React 専用

現状 React（および React ベースのフレームワーク）のみ対応。**Vue.js や Svelte などのプロジェクトには使えない**（同等のコミュニティポートは存在するが公式ではない）。

### 7. Tailwind の知識が必要

コンポーネントのカスタマイズには Tailwind CSS のクラス名の知識が必要。**Tailwindに不慣れな開発者にとっては学習コストが増す**。

## 使うべきケース・使わないべきケース

### ✅ 使うべきケース

| ケース | 理由 |
|--------|------|
| **独自ブランドのデザインシステム構築** | Material Design などに縛られず、ブランドに合わせたカスタマイズが自由 |
| **Tailwind CSS を既に使っているプロジェクト** | スタイリング哲学が一致し、自然に統合できる |
| **中〜大規模な長期プロジェクト** | ベンダーロックインなし、完全な制御権を持てる |
| **アクセシビリティを重視するプロジェクト** | Radix UIベースで高品質なa11y対応が標準 |
| **AIツールを積極的に活用したい開発チーム** | コードがローカルにあるためAIの補完精度が高い |
| **管理画面・ダッシュボード系のUI** | shadcn/ui 自体のサンプルがダッシュボード系に充実 |

### ❌ 使わないべきケース

| ケース | 理由 |
|--------|------|
| **Tailwind CSS を使っていない（使う予定がない）** | Tailwindが前提のため導入コストが高すぎる |
| **高機能データグリッドが必要な業務システム** | 組み込みのDataGridがないため別途ライブラリが必要 |
| **素早くPoC・プロトタイプを作りたい** | セットアップコストに見合わないことがある |
| **React 以外のフレームワーク（Vue, Svelteなど）** | 公式サポートはReactのみ |
| **フロントエンド経験の浅いチーム** | Tailwind + headless UI の理解が必要で学習コストが高い |
| **デザインへの強いこだわりがないシンプルな社内ツール** | MantineやChakra UIの方が素早く実装できることがある |

## まとめ

shadcn/ui は、従来の「インストールして使う」UIライブラリとは根本的に異なるアプローチをとるユニークなツールです。コンポーネントのソースコードをプロジェクト内に直接持つことで、**完全なカスタマイズ性・バンドルの最適化・ベンダーロックインなし**という利点を実現しています。

一方で、Tailwind CSS への依存や、コンポーネント数の少なさなど、万能ではない側面もあります。

### 選択の指針

```
- Tailwind を使っていて、独自デザインシステムを構築したい → shadcn/ui が最適
- Material Design や Ant Design のルックアンドフィールで問題ない → MUI / Ant Design
- シンプルなAPIで素早く作りたい → Chakra UI / Mantine
- データグリッドなど高機能な業務系コンポーネントが必要 → Ant Design / MUI X
```

2024〜2025年にかけて GitHubスター数が急成長（約108k）し、フロントエンド開発における存在感が急速に高まっています。Next.js や Vite を使った React プロジェクトで、デザインの自由度を確保しながら高品質なUIを構築したいチームにとって、shadcn/ui は非常に魅力的な選択肢です。
